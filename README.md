# passgen — менеджер паролей в терминале

Хранит логины и пароли в SQLite, пароли шифрует Fernet, вход — по мастер-паролю.

## Установка

Нужен Python 3.12 (Homebrew):

```sh
/opt/homebrew/opt/python@3.12/bin/python3.12 -m venv .venv
.venv/bin/pip install -e ".[dev]"
```

## Команды

```sh
.venv/bin/passgen add Google            # спросит логин и пароль (Enter — сгенерировать)
.venv/bin/passgen get google            # логин и пароль; регистр названия не важен
.venv/bin/passgen list                  # названия и логины, без паролей
.venv/bin/passgen delete Google [--yes] # без --yes спросит подтверждение
.venv/bin/passgen new [--length 24] [--no-similar] [--save GitHub]
```

`new` генерирует пароль: по умолчанию 20 символов, не короче 8. В пароле всегда есть строчная и
заглавная буквы, цифра и знак. `--no-similar` убирает символы, которые легко спутать: `0 O 1 l I`.
`--save` сразу сохраняет пароль как запись.

Каждая команда сначала спрашивает мастер-пароль. При первом запуске его нужно задать дважды.
Восстановить мастер-пароль нельзя.

## Где лежат данные

В каталоге `data/` относительно места запуска; другой путь задаётся переменной `PASSGEN_DATA`.
Запуск из другого каталога начнёт новое пустое хранилище.

- `vault.db` — записи (пароли зашифрованы) и хеш мастер-пароля;
- `.key` — ключ шифрования, сам зашифрованный мастер-паролем.

Резервная копия — **оба файла вместе**. Без `.key` пароли не расшифровать; программа в этом
случае сообщит об ошибке и новый ключ создавать не будет.

## Как устроено шифрование

- Мастер-пароль хранится хешем PBKDF2-HMAC-SHA256: SHA-256 в 600 000 повторах со случайной солью.
- Ключ Fernet для паролей случайный. В `.key` он лежит зашифрованным ключом, который выводится
  из мастер-пароля тем же PBKDF2, но с другой солью.
- Пароли записей зашифрованы этим ключом Fernet.

Копия `vault.db` и `.key` без мастер-пароля ничего не раскрывает.

## Тесты

```sh
.venv/bin/pytest
.venv/bin/ruff check . && .venv/bin/ruff format --check .
```

### Тесты в Docker

Контейнер прогоняет тесты в Linux на чистой установке пакета. Самой программы в нём нет:
она интерактивная и запускается в вашем терминале.

Запуск — Docker Desktop должен быть открыт. Образ собирается при первом запуске:

```sh
docker compose -f docker/compose.yaml up --build --abort-on-container-exit --exit-code-from tests
```

- `--build` — собрать образ `passgen-tests` (или пересобрать, если код изменился);
- `--abort-on-container-exit` — остановить контейнер, когда тесты закончились;
- `--exit-code-from tests` — код возврата команды равен коду pytest: 0 значит «все тесты прошли».

После прогона в Docker Desktop остаются остановленный контейнер `passgen-tests-1` и образ
`passgen-tests`. Ресурсов они не тратят, только место на диске. Удалить их:

```sh
docker compose -f docker/compose.yaml down --rmi local
```
